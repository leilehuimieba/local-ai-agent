## 方案

- 核心做法：
  - 以“轻量常驻的桌面日历插件”为主入口，而不是聊天框优先
  - 收缩态仅长期显示“当前主目标 + 安全通过概率”
  - 48 小时无关键证据时，概率降为“未知”，并提示“请尽快补充关键证据”
  - 关键证据以“完整且可信的模拟题 / 真题结果”为最高权重
  - 晚间固定查看插件，先交当天证据包，再生成下一步调整建议
  - 每天默认只有 1 个不可协商核心任务，证据包必须包含“下一步调整”
  - 当出现紧急且重要事项时，支持临时切主线；结束后自动恢复原主线优先级结构
  - 迁移时先分类旧能力：保留、降级、迁移、淘汰，优先保证必要能力不断裂
- 状态流转或调用链变化：
  - 日常态：只显示状态，不主动打扰
  - 晚间态：用户主动进入证据包提交
  - 证据态：关键证据进入后先更新安全通过概率，再给出模块级调整建议
  - 过期态：无关键证据时显示“未知”与补证入口
  - 红色态：先要求提交最近现实约束证据，再决定是否降任务量、砍低收益任务或切主线
  - 切主线态：新紧急且重要事项临时升主；结束后自动恢复原主线优先级

## 迁移边界

### 核心保留项

- 必须保留：
  - 现有运行时主链路与可用的执行骨架
  - 现有知识、记忆、verify、browser 等能力作为后续可挂接能力
  - 现有工作区、日志、会话、配置、模型切换等基础设施
- 原因：
  - 本次变更首先是产品语义重定向，不是推翻底层工程资产

### 降级为非核心项

- 默认降级为非核心：
  - 泛问答入口
  - 陪聊型交互
  - 长期人生规划与价值观讨论
  - “什么都能干一点”的通用助理叙事
- 处理方式：
  - 能力继续存在，但不作为首页主入口与主叙事

### 新核心项

- 本轮新增核心：
  - 桌面日历插件常驻壳
  - 当前主目标与安全通过概率主展示
  - 晚间证据包提交入口
  - 模考 / 真题关键证据录入入口
  - 临时切主线与自动恢复规则

### 不立即处理项

- 本轮不做：
  - 全量代码重构
  - 运行时彻底围绕新定义重写
  - 全部历史页面立即迁移到新壳
  - 所有概率与个性化判断一次性实现

## 兼容策略

### 入口兼容

- 短期内保留现有入口，不直接删除或破坏
- 新桌面日历插件作为上层总控入口，逐步接管“先看什么、先做什么、先判断什么”

### 能力兼容

- 现有执行能力先作为“后端能力池”继续保留
- 新系统优先决定主目标、证据、风险与调度，不强迫立即改变所有能力调用协议

### 数据兼容

- 现有会话、知识、记忆、日志、历史记录先不做破坏式迁移
- 后续新增主线总控相关数据时，优先采用增量表或增量字段，不覆盖旧数据语义

### 交互兼容

- 聊天交互保留，但其地位从“主入口”降为“辅助入口”
- 日历插件与总控面板承担“持续可见状态”和“晚间证据闭环”职责

## 分步落地顺序

1. 先固化产品定义与迁移边界。
2. 再定义桌面日历插件的收缩态 / 展开态信息架构。
3. 再定义证据包与关键证据录入协议。
4. 再定义概率更新与过期规则。
5. 再定义临时切主线、记账与自动恢复机制。
6. 最后才拆成独立实现 change 进入代码落地。

## 风险与回退

- 主要风险：
  - 产品语义切换过快，旧能力与新定义互相打架
  - 常驻面板做重，失去“轻量常驻”约束
  - 概率更新过度依赖低质量证据，误导主目标判断
  - 临时切主线过于频繁，导致主线失焦
- 回退方式：
  - 保留旧入口与旧能力，先不删除、不硬破坏
  - 迁移过程中以文档与配置层变更为主，功能层按 change 分步落地
  - 若新定义未稳定，允许回退到原有“本地智能体”口径，但保留新文档与兼容说明
  - 所有切主线与高风险调整必须可记账、可复盘、可恢复
