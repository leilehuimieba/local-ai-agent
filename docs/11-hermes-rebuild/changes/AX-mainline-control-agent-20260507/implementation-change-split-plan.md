# 后续实现 change 切分建议

## 目标

把 `AX-mainline-control-agent-20260507` 的产品定义与治理文档，拆成后续可独立推进、可独立验收、可独立回退的实现 change，避免一次性把桌面插件、证据闭环、概率系统、切主线逻辑混写到同一轮开发里。

## 切分原则

1. 先做入口壳，再做判断与治理。
2. 先做最小闭环，再做个性化增强。
3. 每个 change 必须有单独验证证据，不共享“应该差不多好了”的口径。
4. 每个 change 默认只解决一个主问题，不抢其他 change 的边界。

## 建议切分

### AY-desktop-calendar-shell-20260507

#### 目标

实现桌面日历插件常驻壳，形成“开机可见、收缩态可用、展开态可进”的最小总控入口。

#### 范围

1. 轻量常驻壳
2. 收缩态：当前主目标 + 安全通过概率 / 未知状态
3. 展开态：今日任务、本周目标、最终目标、证据入口
4. 晚间固定查看入口

#### 不做

1. 不实现复杂概率判断
2. 不实现完整切主线逻辑
3. 不实现深度个性化

#### 验收点

1. 开机后插件可轻量常驻
2. 收缩态字段正确展示
3. 48 小时无关键证据时可显示“未知”与补证入口
4. 展开态能进入晚间证据包与关键证据录入入口

### AZ-evidence-packet-loop-20260507

#### 目标

实现晚间证据包闭环，使“晚上回插件先交证据包”成为真正可执行的日常动作。

#### 范围

1. 固定核心字段
2. 可变补充字段
3. 晚间提交
4. 次日中午前补交窗口
5. 未补交后的状态流转

#### 不做

1. 不做完整模考驱动的大概率更新
2. 不做复杂个性化推荐

#### 验收点

1. 晚间可提交一份完整证据包
2. 支持次日中午前补交
3. 未补交时系统能进入待处理状态
4. 证据包能产出“下一步调整”字段

### BA-key-evidence-and-probability-20260507

#### 目标

实现“模考 / 真题结果 -> 概率更新 -> 模块级调整建议”的最小判断闭环。

#### 范围

1. 模考 / 真题关键证据录入
2. 可信性门槛校验
3. 总分录入与分项补全
4. 单次小改 / 连续趋势大改
5. 48 小时无关键证据时降为未知

#### 不做

1. 不做高度复杂的长期个性化模型
2. 不把所有普通学习记录都纳入概率更新

#### 验收点

1. 完整且可信的模考结果可更新概率
2. 不完整考试条件结果不会直接改概率
3. 关键证据缺失 48 小时后，概率会降为未知
4. 概率更新后能生成模块级调整建议

### BB-temporary-mainline-switch-20260507

#### 目标

实现“紧急且重要事项 -> 临时切主线 -> 自动恢复原主线优先级结构”的治理闭环。

#### 范围

1. 用户提出切主线
2. Agent 复核
3. 用户坚持时的记账
4. 临时主线接管
5. 结束后自动恢复原主线优先级结构

#### 不做

1. 不把所有普通插单都升级成切主线
2. 不做复杂多主线并发调度

#### 验收点

1. 可以发起一次临时切主线
2. 系统能记录复核意见与用户坚持
3. 切换期间原主目标降级
4. 临时主线结束后能自动恢复原主线优先级结构

### BC-capability-classification-and-entry-degrade-20260507

#### 目标

把现有能力按“保留 / 降级 / 迁移 / 淘汰”分类，并把旧入口从主入口降为辅助入口，避免新旧产品语义继续混杂。

#### 范围

1. 能力分类表落地
2. 旧入口定位重写
3. 首页主叙事切换为主线总控
4. 非核心能力降级说明

#### 不做

1. 不删除旧能力实现
2. 不在本轮做重度底层清理

#### 验收点

1. 已有能力分类清楚
2. 首页或主入口口径不再以“泛本地智能体”叙事为主
3. 非核心能力仍可用，但不再抢主入口

### BD-personalized-roi-followup-20260507

#### 目标

在已有通用判断之上，开始积累“先通用、后个性化”的个人 ROI 模型，为“越来越了解你”提供真实证据基础。

#### 范围

1. 记录不同任务类型的完成率
2. 记录不同任务类型对结果变化的贡献
3. 初步识别个人高 ROI 任务类型

#### 不做

1. 不在首轮就做复杂机器学习或黑箱评分
2. 不替代 BA 的通用概率判断主链

#### 验收点

1. 系统能沉淀用户级任务效果数据
2. 能基于历史证据给出初步“更适合你”的方向提示

## 推荐推进顺序

1. AY：先做桌面日历插件壳
2. AZ：再做晚间证据包闭环
3. BA：再做关键证据与概率系统
4. BB：再做临时切主线
5. BC：再做入口降级与能力分类落地
6. BD：最后做个性化 ROI 跟进

## 最小验证策略

### 第一阶段验收

完成 AY + AZ 后，应该证明：

1. 插件已成为真实入口
2. 用户每天晚上能回到系统交证据

### 第二阶段验收

完成 BA 后，应该证明：

1. 关键证据能真实更新安全通过概率
2. 概率过期会降为未知

### 第三阶段验收

完成 BB 后，应该证明：

1. 短窗硬目标能合法切主线
2. 结束后原主线能自动恢复

### 第四阶段验收

完成 BC + BD 后，应该证明：

1. 新叙事已稳定接管主入口
2. 系统开始从“通用判断”过渡到“更懂你”的个性化判断
