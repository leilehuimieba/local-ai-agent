# 变更提案

## 为什么做

`BN` 已让今天计划独立呈现，并让晚间证据开始对账，但系统仍缺一个最小历史闭环：

1. 今天计划完成后，缺少最近几次计划执行留痕。
2. 无法快速回看“哪天生成 / 哪天接管 / 是否完成 / 是否收尾”。
3. `store.ts` 已超过 1400 行，若继续把计划逻辑堆在里面，后续会越来越难维护。

## 做什么

1. 新增最近计划历史记录，保留最小必要字段。
2. 在主壳中展示最近计划记录摘要。
3. 将计划摘要 / 对账 / 历史相关逻辑从 `store.ts` 抽到独立模块，作为热点拆分第一步。

## 不做什么

1. 不做跨会话持久化。
2. 不做完整周历史或统计图。
3. 不做后端同步。

## 验收标准

1. 计划接管 / 完成 / 收尾后，可在主壳看到最近计划历史摘要。
2. 历史记录至少包含：目标日期、今日任务、最终状态、最后更新时间。
3. `store.ts` 中计划摘要与历史逻辑不再内联堆叠，迁到独立文件。
