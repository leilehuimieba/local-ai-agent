# 变更提案

## 背景

- `BF-next-day-plan-and-restore-20260507` 已完成“当天证据 -> 明日计划”的第一层闭环，但用户的真实使用动作还差一段关键规则没有产品化。
- 当前插件还不能明确回答：
  - 今晚是不是到了固定查看时间
  - 昨晚没交证据时，现在是该补昨天，还是直接保今天
  - 次日中午后若仍未补交，系统应该怎么分流
- 这会导致“晚间证据包”已经存在，但“什么时候交、错过后怎么办”仍停留在口头规则。

## 目标

- 本次要完成什么：
  - 为主线总控壳补上“晚上固定查看”状态卡
  - 支持“次日中午前补交昨晚证据”的状态流转
  - 超过补交窗口后，给出“先补昨天 / 继续今天”的插件内裁决
  - 让晚间证据入口的按钮文案和状态提示与补交流程一致

## 非目标

- 本次明确不做什么：
  - 不接真实系统提醒、桌面通知或闹钟
  - 不做跨天持久化恢复
  - 不引入真实日历写回或自动排期
  - 不改变关键证据概率模型本身

## 验收口径

- 通过标准：
  - 展开主线总控壳后，可见“晚上固定查看”状态卡
  - 次日上午会进入“昨晚证据可补交”状态
  - 次日中午后会进入“补交窗口已过”的分流状态
  - 晚间证据入口文案可随状态切换
  - 文档、实现与测试口径一致
