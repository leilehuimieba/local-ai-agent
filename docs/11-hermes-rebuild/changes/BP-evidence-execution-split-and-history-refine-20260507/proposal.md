# 变更提案

## 为什么做

`BO` 已完成最近计划历史最小闭环，并把计划簇逻辑开始从 `store.ts` 外提，但两个热点仍然明显：

1. evidence 提交流程与关键证据评估仍堆在 `store.ts`。
2. execution 迁移 / 收尾 / 今日完成仍堆在 `store.ts`。
3. 最近计划历史目前只有状态文本，还缺少“是否已完成 / 是否已对账”的更细判断。

## 做什么

1. 新增 `evidence-flow-rules.ts`，抽出 evidence 相关状态流转。
2. 新增 `execution-flow-rules.ts`，抽出 execution 相关状态流转。
3. 细化计划历史状态，增加“是否已完成对账”判断。

## 不做什么

1. 不做后端持久化。
2. 不做统计图表。
3. 不做完整 store 大拆分，只做证据簇和执行簇第一步外提。

## 验收标准

1. `store.ts` 中 evidence / execution 大段派生逻辑被外提到独立规则文件。
2. 最近计划历史能区分“已收尾但未对账”和“已收尾且已对账”。
3. 现有主壳行为与测试保持通过。
