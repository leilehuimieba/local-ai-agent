# 变更提案

## 为什么做

`BK` 已经解决“昨天执行态不能压住今天动作”，但明日计划仍然缺一个关键治理能力：

1. 计划不知道自己是为哪一天生成的。
2. 计划不知道自己依据的是哪一天的关键证据。
3. 一旦跨天或关键证据变化，系统不会明确告诉用户“这份计划已经该重算了”。

## 做什么

1. 给明日计划补上目标日期与证据日期归属。
2. 在主壳中显示计划当前状态、目标日期、依据证据日期。
3. 跨天后若进入计划目标日但今天尚未接管主线，提示计划待重算。
4. 关键证据更新后，旧计划显示“不是最新版本”。

## 不做什么

1. 不做真实跨会话持久化。
2. 不做周计划或复杂排程。
3. 不改概率模型本身，只做计划状态治理。

## 验收标准

1. 明日计划生成后可看到目标日期与证据日期。
2. 到达目标日但今天尚未重开主线时，会提示计划待重算。
3. 关键证据变化后，旧计划会显示已失效或不是最新版本。
