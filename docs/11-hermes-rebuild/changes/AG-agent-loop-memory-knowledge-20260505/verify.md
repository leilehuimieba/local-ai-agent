# 验证方案

## 文档级验收

本 change 当前是蓝图 change，不以代码测试通过为验收口径，而以“是否足够指导后续实现”作为第一层验收。

必须满足：

1. 能明确回答“当前补的是哪层壳”。
2. 能明确回答“先改哪些模块”。
3. 能明确回答“为什么先改这一层，而不是继续扩工具或 UI”。
4. 能明确回答“每一刀要补什么验证证据”。

## 后续实现的验证要求

### 第一刀：主循环最小升级

至少补齐：

1. 多步回路单元测试；
2. replan 触发测试；
3. iteration budget 耗尽后 handoff 证据。

### 第二刀：上下文 profile

至少补齐：

1. ask / act / repair / learn profile 选择测试；
2. 不同 profile 的注入差异证据；
3. 恢复态不会误注入无关大段知识摘要。

### 第三刀：记忆分层与 recall

至少补齐：

1. episodic / semantic / procedural 写回路由测试；
2. recall 按问题类型重排测试；
3. 记忆污染与去重规则测试。

### 第四刀：知识检索与回答 pack

至少补齐：

1. 混合检索命中测试；
2. `knowledge pack` 结构稳定性测试；
3. 至少 3 个 agent 工程问题的问答回归样例。

### 第五刀：verify 矩阵

至少补齐：

1. 文件修改类 verify；
2. 命令执行类 verify；
3. 知识回答类 verify；
4. 记忆写入类 verify；
5. 浏览器交互类 verify。

## 建议回归问题集

后续实现完成后，至少用下面问题回归：

1. `agent 是什么`
2. `为什么 agent 需要 memory 和 context engineering`
3. `如何评估一个 agent 是否可靠`
4. `这个项目下一步最该补哪层外壳`
5. `如果当前任务失败，应该继续硬跑还是进入 handoff`
