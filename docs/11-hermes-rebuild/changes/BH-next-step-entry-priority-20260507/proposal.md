# 变更提案

## 背景

- `BG-evening-review-and-late-evidence-branch-20260507` 已把晚上固定查看、补交窗口和超时分流做出来，但主壳仍然主要是在“展示判断”。
- 用户下一步真正需要的是：
  - 当前最应该点哪个入口
  - 概率未知时是否应直接优先补关键证据
  - 晚间证据提交后，是先补关键证据还是先生成明日计划
- 如果这层不落地，系统仍然需要用户自己读完状态再二次判断，督战总控感还不够强。

## 目标

- 本次要完成什么：
  - 在主壳里新增“下一步动作”主按钮
  - 当概率未知时，把主按钮优先切到关键证据录入
  - 当晚间证据已提交且概率已知时，把主按钮优先切到明日计划
  - 当补交窗口已过且裁决为“继续今天”时，把主按钮优先切到时间预算接管

## 非目标

- 本次明确不做什么：
  - 不接真实系统提醒或桌面通知
  - 不做跨天持久化
  - 不改动关键证据评分模型本身
  - 不引入复杂多按钮编排系统

## 验收口径

- 通过标准：
  - 主壳可见“下一步动作”摘要卡与主按钮
  - 概率未知时，主按钮优先进入关键证据录入
  - 晚间证据已提交且关键判断已知时，主按钮优先生成明日计划
  - 超时且裁决“继续今天”时，主按钮优先进入时间预算接管
  - 文档、实现与测试口径一致
