# 变更提案

## 背景

- 本次变更要解决的问题：MCP 注册表主链已收口，但“浏览器自动化”仍停留在独立 skill / 调试能力，尚未成为 Runtime 可稳定调度的正式执行入口。
- 对应阶段目标：自由迭代期里，把浏览器操作从“外部能力储备”推进到“主链可调用、可验证、可审计”的产品级执行能力。

## 目标

- 本次要完成什么：为 Runtime 打通一条最小可用的浏览器自动化主链，至少覆盖页面打开、页面读取、基础交互与结果回传的正式接入口。

## 非目标

- 本次明确不做什么：不建设完整浏览器 IDE，不扩多浏览器 provider 适配层，不在首刀里接入高复杂度登录态管理、下载管理或视觉级回放系统。

## 验收口径

- 通过标准：Runtime 能把浏览器动作作为正式工具纳入主链；Gateway 或既有浏览器执行层能稳定承接请求；至少补齐一条接口级或端到端验收证据，证明浏览器动作可被真实调起并返回结果。
