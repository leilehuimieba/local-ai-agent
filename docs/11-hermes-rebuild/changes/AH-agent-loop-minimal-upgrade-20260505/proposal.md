# 变更提案

## 背景

- 当前项目已经具备稳定的单次运行主链，但 `planner -> query_engine -> lib` 仍偏“单动作收口”，复杂任务需要人工多轮接力。
- `AG-agent-loop-memory-knowledge-20260505` 已明确后续优化顺序应为 `主循环 -> 上下文 -> 记忆 -> 知识 -> verify`，因此第一刀必须先把主循环升级为受控多步回路。
- 本次变更只承接蓝图中的第一刀，目标是为后续上下文 profile、记忆路由、知识 pack、verify 矩阵提供稳定执行骨架。

## 目标

- 产出一个只覆盖“主循环最小升级”的实现 change 工作区，作为后续代码实现与验收的唯一入口。
- 冻结第一刀范围：`PlanEnvelope + 小步回路 + replan 事件 + iteration budget 耗尽后的 handoff`。
- 明确第一刀要改的 Runtime 模块、事件字段、测试证据与回退边界。

## 非目标

- 不在本 change 中实现上下文 profile。
- 不在本 change 中实现记忆分层、知识检索升级或 verify 矩阵。
- 不引入多智能体编排、复杂 DAG planner 或无限自动修复。
- 不改写 Rust / Go / Frontend 的既有职责边界。

## 验收口径

- 通过标准：
  - 文档范围仅覆盖主循环最小升级，没有混入记忆、知识检索、verify 设计。
  - 已明确第一刀的改造落点、任务清单、验证证据与回退方式。
  - 后续实现型智能体可直接据此进入代码改造，而不需要重新拆范围。
