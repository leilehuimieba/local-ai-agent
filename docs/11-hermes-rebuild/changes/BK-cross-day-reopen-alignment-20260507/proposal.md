# 变更提案

## 为什么做

`BJ` 已经引入执行态，但它仍然默认“今天”的状态只活在当前页面时刻里。
一旦跨到第二天，昨天的“已收尾 / 正在执行”如果继续留在界面上，就会压住今天真正该做的动作。

当前最明显的风险有两个：

1. 昨天已收尾，今天却仍显示“今天已收尾”，导致主按钮失真。
2. 昨天未收尾，今天若直接沿用昨天执行态，会绕过新的现实时间预算判断。

## 做什么

1. 给执行态补上日期归属。
2. 跨天时自动把昨天执行态重置为“今天待重开”。
3. 已收尾跨天与未收尾跨天给出不同提示。
4. 对齐晚间补交流程与执行态日期边界，避免昨天状态压住今天主线。

## 不做什么

1. 不做跨天持久化存储。
2. 不做真实系统日历同步。
3. 不扩复杂周计划或多日排程。

## 验收标准

1. 跨天后昨天执行态不会继续直接沿用。
2. 昨天已收尾与昨天未收尾有不同重开提示。
3. 跨天后主按钮会切到“重开今天主线”或“优先补关键证据”。
